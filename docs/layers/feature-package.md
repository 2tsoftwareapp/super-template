# A feature package

One package per bounded context that owns data: its tables, its HTTP surface, its
tests. Composition lives in `apps/api`; behaviour lives here.

```
packages/feature-<id>/
  package.json     exports ".", "./contracts", "./schema", "./module" (never "./*")
  turbo.json       {"extends":["//"],"tags":["layer:feature"]}
  README.md        what this feature owns (generated by scaffold, then edited)
  src/
    <id>.feature.ts    FeatureManifest: id, nestModule, schema, httpPipeline
    <id>.module.ts     Nest wiring only
    application/       orchestration: use-cases, services, ports
    domain/            pure rules + invariants
    infrastructure/    Drizzle repositories, external adapters
    presentation/      controllers, DTOs
    __tests__/         specs live next to what they test
```

## Rules

- **A layer is optional.** Create `domain/` only when there are rules worth
  testing on their own; create a use-case only when it owns a transaction or
  coordinates ≥2 collaborators.
- **A port needs a reason**: two implementations, a process boundary, or a
  cross-feature seam. Otherwise inject the class.
- **One exported class per file**, kebab-case names, ≤300 lines.
- **No cross-feature imports** except `@repo/feature-x/contracts|schema|module|testing`.
- **Tests**: `src/**/__tests__/<subject>.spec.ts`; HTTP flows go to
  `apps/api/test/*.e2e.spec.ts`.

Layer details: [application](application.md) · [domain](domain.md) ·
[infrastructure](infrastructure.md) · [presentation](presentation.md).
Global contract: `AGENTS.md`, `docs/CONVENTIONS.md`.
