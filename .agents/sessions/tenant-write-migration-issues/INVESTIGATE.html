Làm thế nào để đảm bảo 100% data integrity giữa object storage, business data và audit logs trong mọi trường hợp failure? Làm sao để đồng bộ hóa hoàn toàn context scope của SUPER_ADMIN và E2E tests?

Impact

  • Data Integrity: High. Dễ sinh ra orphan object hoặc DB soft delete mà không có audit, không truy vết được.
  • UX: Medium. Thiếu warning khi file bị cắt.
  • Security / ACL: High. E2E test không phản ánh đúng behaviour của production. Scope list/export bị lệch.

Recommendation

  • Fix 1 (Atomicity): Sửa DeleteFile, DeleteAttachment, ConfirmImport, CreateExport, UpdateSetting để sử dụng transaction port đúng chuẩn. Các lệnh xoá storage phải chuyển về sau khi commit (hoặc sử dụng outbox nếu có). Nếu không có outbox, thực hiện softDelete + audit trong 1 TX, sau đó mới xoá object.
  • Fix 2 (Cleanup Export): Đưa logic upload ra ngoài, sau đó dùng try { ... runInTx(...) } catch (e) { storage.delete() } để dọn dẹp CSV bị lỗi khi DB lỗi.
  • Fix 3 (Truncated): Đổi isTruncated ở backend về truncated để tương thích với FE.
  • Fix 4 (Scope): Bổ sung explicitly filter scope cho query builder để List và Export đồng bộ hành vi.
  • Fix 5 (Purge loop): Chuyển PlatformTransactionPort.run vào bên trong vòng lặp while của hàm purge để commit từng mảng 5000 rows.
  • Fix 6 (E2E): Sửa symbol DATABASE trong E2E và bổ sung context no-org cho interceptor test.
